# 📅 일일 개발 리포트 (2026-02-25)

## 🚀 Post Flow: 불러오기 기능 완성 및 자동화 패러다임 전환 준비

### 1. 주요 작업 내용
오늘은 앱의 사용성을 높이는 '불러오기' 기능을 완성하고, 네이버 자동화의 고질적인 문제였던 레이어 간섭 문제를 해결했습니다. 또한, 더 완벽한 자동화를 위한 '템플릿 방식'이라는 새로운 전략을 수립했습니다.

#### ✅ 성과 (Achievements)
1.  **불러오기(History Load) 기능 구현:**
    *   **DB 고도화:** 기존 제목만 저장하던 방식에서 본문, 레고 블록 구조, 사진 경로, 팩트 체크 정보를 통째로 저장하도록 DB 스키마를 재설계했습니다.
    *   **홈 화면 UI:** 하단에 최근 5개의 발행 이력을 리스트로 보여주고, 클릭 시 에디터로 모든 데이터를 즉시 복원하는 로직을 완성했습니다.
2.  **네이버 자동화 "도움말 창" 정복:**
    *   **전방위 청소:** `mainFrame` 뿐만 아니라 브라우저의 모든 프레임을 순회하며 도움말 및 팝업 레이어를 JavaScript로 강제 삭제하는 `aggressive_cleanup` 로직을 구축했습니다.
    *   **정밀 타격:** 좌표 계산 기반의 마우스 클릭과 `force: True` 옵션을 조합하여 방해물에 상관없이 '저장' 버튼을 누르는 데 성공했습니다.
3.  **시스템 구조 재편 (레고 블록 방식):**
    *   단순 텍스트 전달이 아닌, AI가 `sticker`, `quote`, `map` 등 에디터 기능을 블록 단위로 설계하여 전달하는 방식을 도입했습니다.
4.  **안정성 및 디버깅 최적화:**
    *   Gemini 모델을 할당량이 넉넉한 `gemini-flash-latest`로 변경하여 429 에러를 방지했습니다.
    *   자동화 창의 높이를 조절(500px)하여 터미널 로그 가독성을 확보했습니다.

### 2. 기술적 수정 사항 (Technical Details)
- **Backend:** `posts.py` 엔드포인트에서 `blocks` 데이터 처리를 추가하고, `gemini_service.py` 프롬프트를 블록 리스트 생성 방식으로 개조했습니다.
- **Automation:** `naver.py`에서 `Tab` 키 대신 직접적인 영역 클릭과 좌표 기반 저장 로직을 적용했습니다.
- **Frontend:** `PostProvider`와 `ApiService`가 새로운 `blocks` 데이터를 주고받도록 업데이트했습니다.
