## 🎯 방향 정리 (오늘 정한 것)
- 발행할 블로그는 이미 직접 쓴 맛집 글이 있는 **함께 운영하는 공개 블로그**다. 같은 블로그가 글쓰기 스타일 학습 재료다.
- **1순위:** AI가 쓴 글이 기존 글과 같은 사람이 쓴 것처럼 보여야 한다. 어느 글만 느낌이 다르면 실패다.
- **2순위 ("조금 더 이쁘게"):** 사진 설명을 조금 더 풍부하게, 재방문 의사 표시, 내돈내산 표기(영수증 사진 활용), 검색 노출용 제목. 이 4가지 외의 문체는 바꾸지 않는다.
- 런타임 AI는 당분간 Gemini를 유지한다. Claude Code는 개발과 1회성 분석을 맡는다.

### 2. [Backend] 가게 정보 부분 수정이 항상 실패하던 버그 수정 (`784540a`)
- **증상:** `/posts/patch`가 `argument of type 'NoneType' is not iterable`로 실패했다.
- **원인:** `patch_sections`가 모든 블록의 `value`에 `in` 검사를 했는데, 사진/구분선 블록은 `value`가 `None`이다. AI가 쓴 글에는 사진 블록이 거의 항상 있어서 이 기능이 사실상 동작하지 않았다.
- **수정:** `(b.value or "")`로 비교한다.
- **확인:** 고치기 전에 서버 API로 재현했고, 고친 뒤 함수를 직접 호출하는 방법과 서버 API 호출로 다시 확인했다.
- **겪은 일:** 코드를 고친 뒤에도 예전 에러가 계속 났다. `reload=True`의 자동 재시작이 Windows에서 끝나지 않고 멈춰 있었다. 함수를 서버 없이 직접 호출해서 "코드 문제인지 서버 상태 문제인지"를 나눠 확인했고, 서버를 다시 켜서 해결했다.

### 4. [Backend] 1단계: 블로그 크롤러를 블록 단위 추출로 재작성 (`blog_crawler.py`)
- **기존:** RSS로 글 목록을 받고, 글마다 Playwright 브라우저를 띄워 **텍스트만** 가져왔다. 사진 위치, 인용구, 지도 같은 포맷 정보가 모두 사라졌다.
- **변경:** 브라우저 없이 `httpx`로 `PostView.naver` HTML을 받고 `beautifulsoup4`로 스마트에디터 컴포넌트를 순서대로 읽는다.
  - `parse_post_blocks(html)` → `text` / `image`(사진 장수, 캡션) / `quote`(레이아웃 style) / `map`(가게명, 주소) / `divider` / `other`
  - `crawl_all(..., category="맛집")`로 카테고리를 거를 수 있다.
  - 기존 `content`(평문) 필드는 그대로 유지해서 스타일 분석 코드가 깨지지 않는다.
- **이유:** PostView 페이지는 본문이 서버에서 HTML로 렌더링되어 오기 때문에 브라우저가 필요 없다. 더 빠르고, Windows 이벤트 루프와 async Playwright 충돌 문제도 피한다.
- **확인:** 가짜 HTML로 만든 단위 테스트 8개 통과(`backend/tests/test_blog_crawler.py`, 표준 `unittest`). 실제 맛집 글 5편 크롤링 성공, 모르는 컴포넌트 0개.
- **한계:** RSS에는 최신 글 몇 개만 있다. (오늘 기준 6개, 그중 맛집 5개)

### 5. [Docs] 2단계: 블로그 포맷 명세서 작성 (`docs/blog_format_spec.md`)
- 크롤링한 5편을 분석해서 글 구조, 사진 묶음, 가게 정보 인용구, 문체, 인사/맺음말, 제목 패턴, "이쁘게" 범위, 앱에 필요한 변경을 정리했다.
- 데이터로 확인한 수치: 사진 블록 60개 중 **2장 묶음 62%**, 1장 22%, 3장 17%. 글 한 줄 길이 **중앙값 13자**(절반이 10~16자).
- 기존 앱 포맷과의 큰 차이: 섹션 제목(`[외관]` 등)이 없고, 짧은 줄바꿈이 많고, 가게 정보에 지도 블록을 쓰고, 단점도 솔직하게 쓴다.
- 저장소가 공개이므로 블로그 원문 문장, 실제 주소, 영업시간은 넣지 않았다. 원문과 연속 10글자 이상 겹치는 부분이 없는지 스크립트로 확인했다(포맷 이름표 제외).
