## 🎯 방향 정리 (오늘 정한 것)
- 고치는 방법은 **메모 → AI가 메모마다 고친 안 + 의견 → 승인/거절/답장**. 승인한 안만 미리 본 그대로 들어간다.
- AI가 고칠 수 있는 범위는 **메모 단 글 + 바로 앞뒤 글 하나씩**. 사진 묶음·지도·구분선은 건너뛰고, 인용구(가게 이름·정보)에서 멈춘다. 블록 수는 바뀌지 않는다.
- 검수 흐름: [검수 받기] → 검수 화면에서 전체 내용을 먼저 본다 → [검수 내용 편집하러 가기] → 지적이 달린 글 옆에서 고친다. (사용자 결정: 전체 지적을 알고 나서 편집하고 싶다)
- 글 전체 고쳐쓰기(`/revise`)는 남기되 작은 버튼으로. 개선은 하지 않는다.
- 작업 중인 글은 서버 DB가 아니라 **노트북 파일**에 자동 저장한다 (한 대에서만 쓰고, 서버가 꺼져 있어도 저장되게).

## 🛠️ 상세 작업 내용

### 1. [Backend] 메모 고치기 API `POST /posts/memo-edit` (`38a9ef1`, `ea3eaca`)
- `services/memo_editor.py`: 체크한 메모 전체를 **AI 1회 호출**로 처리한다 (Sonnet, effort medium).
- AI는 고친 글(`value`)만 낸다. **원래 글(`before`)은 서버가 실제 블록에서 채운다** → 앱에 보이는 "원래 → 고친 글"이 항상 실제 글과 같다.
- 범위 밖 블록, text가 아닌 블록, 빈 내용, 같은 블록 두 번은 코드가 버리고 `notes`에 이유를 남긴다.
- 답장하면 앞의 안·의견·답장을 대화(`thread`)로 붙여 그 메모만 다시 보낸다. 검수 질문에 쓴 답도 사실 근거로 넣는다.
- **'사실' 검수 메모에는 바로 앞 사진 묶음을 첨부한다** (호출당 최대 6장). 첫 실제 시험에서 검수가 틀리게 지적한 입간판 문구("20년 가까이")를 AI가 그대로 지웠다. 메모 고치기 AI도 사진 설명만 봐서 확인할 수 없었기 때문이다. 사진을 붙인 뒤에는 "사진 1의 입간판에 '… 20년 가까이 …'라는 문구가 보여서 그대로 뒀어요"로 바뀌었다 (사진 2장에 약 $0.005 추가).

### 2. [Backend] 검수 지적에 문제 문장 `quote` (`6e4e006`)
- 검수 AI가 문제 부분을 글에서 그대로 옮겨 적게 했다. 서버가 실제 글에 있는지 확인하고 없으면 비운다(엉뚱한 곳을 칠하지 않도록).
- 실제 검수 1회: 지적 12개 중 11개에 quote, 모두 글과 일치. 빈 1개는 지도 블록 지적(원래 메모로 옮기지 않음).

### 3. [App] 메모 상태와 승인 규칙 (`c8730cd`, `01baa11`)
- `lib/providers/memo_logic.dart`: 순수 함수로 나눠 `flutter test`로 확인한다.
- **승인은 AI를 다시 부르지 않는다.** 안의 원래 글이 지금 글과 같을 때만 넣는다. 다른 안을 먼저 승인했거나 직접 고쳐서 달라졌으면 승인을 잠그고 "답장해서 다시 요청"을 안내한다.
- 섹션을 지우거나 사진 블록이 끼워지면 메모·받은 안의 블록 번호를 맞춘다. 같은 이유로 '고침' 초록 테두리가 엉뚱한 블록에 붙던 원래 버그도 같이 고쳤다.
- 다시 검수하면 보내지 않은 검수 메모만 새 지적으로 바꾸고, 안을 받았거나 끝난 메모는 남긴다.

## 🐞 작업 중 실수와 교훈
- **셸 heredoc이 `\n`을 바꾼다 (어제와 같은 실수):** 파이썬 스크립트로 코드를 넣다가 문자열이 실제 줄바꿈이 되어 문법 오류, 또는 바꿀 위치를 못 찾았다. 스크립트는 파일로 저장해 raw 문자열로 넣거나 Edit 도구를 쓴다.
- **`dart format`을 파일 전체에 돌리지 않기:** 상관없는 240줄이 바뀌어 되돌렸다. 바꾼 부분만 맞춘다.
- **가짜 서버의 한계를 먼저 말하기:** 가짜 서버가 메모를 위치로만 찾아서, 다른 메모의 실제 결과를 엉뚱하게 보여 줬다. 사용자가 "(가짜 서버가 넣은 줄)이 뭐냐"고 물은 뒤에야 설명했다.
- **테스트가 실제 버그를 잡았다:** 메모 창을 닫자마자 입력 칸 controller를 정리해서, 닫히는 애니메이션 중에 에러가 났다. `ValueKey<dynamic>`과 `ValueKey<String>`은 다른 키다.
