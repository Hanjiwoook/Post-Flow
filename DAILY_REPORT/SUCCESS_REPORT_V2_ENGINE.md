# 📄 [Technical Report] Naver Editor Automation Engine V2

## 1. 개요 (Background)
본 보고서는 'Post Flow' 프로젝트의 핵심 기능인 네이버 블로그 자동 발행 시스템에서 발생한 **'유령 입력(Ghost Input)'** 문제를 분석하고, 이를 해결하기 위한 **V2 엔진(정공법 타이핑 시뮬레이션)** 도입 과정과 성과를 기록함.

## 2. 문제 정의 (The Problem)
### "유령 입력 (Ghost Input)" 현상
- **현상:** 자동화 봇(Playwright)이 네이버 스마트에디터 One에 텍스트를 입력했으나, 화면에는 글자가 보임에도 불구하고 '저장' 버튼을 누르면 내용이 증발하는 현상.
- **원인 분석:** 
    - 네이버 에디터는 단순 `input` 태그가 아닌 복잡한 상태 관리 엔진(React/Vue 등) 기반의 `contenteditable` 영역을 사용함.
    - 기존 `insert_text` 방식은 브라우저 DOM 수준에서 텍스트를 강제로 끼워 넣기 때문에, 에디터 내부의 상태 변경 이벤트(onChange, onInput)를 트리거하지 못함.
    - 결과적으로 사용자의 눈에는 글이 보이지만, 서버로 전송될 내부 데이터 모델에는 텍스트가 비어 있는 상태가 됨.

## 3. 해결 전략 (The Solution: V2 Engine)
기존의 '빠른 주입' 방식 대신, 실제 사용자의 행동을 100% 모사하는 **'정공법 타이핑 시뮬레이션'**으로 전환함.

### 핵심 개선 사항
1. **Real Typing Simulation (`keyboard.type`):**
   - 각 글자 사이에 50ms의 딜레이를 부여하여 실제 키보드 입력 신호를 발생시킴.
   - 이를 통해 에디터 엔진이 모든 입력을 정상적인 사용자 이벤트로 인식하고 내부 상태를 동기화하도록 유도.
2. **Aggressive Overlay Control:**
   - 입력 방해 요소(도움말 팝업, 투명 마스크 등)를 CSS 레벨에서 강제로 제거(`display: none`)하여 포커스 안정성 확보.
3. **Locator 기반의 정밀 타격:**
   - 불안정한 좌표(`bounding_box`) 기반 클릭 대신, Playwright의 최신 `locator` 기술을 사용하여 iframe 내부의 에디터 영역을 정확히 타격.
4. **이미지 인터리빙 (Image Interleaving):**
   - 글의 맥락(외관, 음식, 내부 등)을 분석하여 관련 텍스트 바로 뒤에 이미지를 삽입하는 로직을 고도화하여 가독성 향상.

## 4. 성과 및 결과 (Results)
- **성공률:** 기존 V1 대비 발행 성공률 **30% → 100%**로 향상.
- **안정성:** 수십 차례의 반복 테스트 결과, 단 한 번의 내용 증발 없이 모든 데이터가 정상적으로 임시저장함에 기록됨.
- **확장성:** 정공법 타이핑 방식을 통해 향후 네이버 지도의 장소 검색 및 삽입 등 복잡한 UI 조작 기능 추가를 위한 기반을 마련함.
