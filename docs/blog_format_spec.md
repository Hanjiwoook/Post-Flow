# 블로그 포맷 명세서 (맛집 리뷰)

AI가 쓴 글이 **기존 블로그 글과 같은 사람이 쓴 것처럼** 보이게 하기 위한 기준이다.
3단계(글쓰기 프롬프트 교체), 4단계(편집 화면), 5단계(네이버 발행 봇)가 이 문서를 따른다.

- 근거: 블로그 맛집 카테고리 글 5편 (2026-04 ~ 2026-05), `blog_crawler.parse_post_blocks`로 블록 단위 추출
- 작성: 2026-11-12. 새 글이 쌓이면 다시 크롤링해서 확인한다.
- 원칙: **1순위는 "같은 사람의 글처럼 보이기"**, 2순위가 "조금 더 이쁘게". 둘이 부딪히면 1순위를 따른다.

---

## 1. 글 전체 구조

```
① 글      인사 + 날씨/상황 한마디 + "오늘은 ○○ 다녀왔어요"
② 인용구   가게 이름만                         (style: default)
③ 지도     네이버 지도 장소 블록
④ 인용구   가게 정보 (이모지 항목, 아래 3절)     (style: quotation_line)
⑤ 글      방문 시점·웨이팅 (사진 없이 시작해도 됨)
⑥ 반복     [사진] → [그 사진을 설명하는 글]      ← 6~11번
⑦ 마지막 글 안에 총평과 맺음말 (아래 5절)
```

- **섹션 제목이 없다.** `[외관]` 같은 태그 없이 사진과 글이 자연스럽게 이어진다.
- **구분선(divider)을 쓰지 않는다.**
- 여러 가게를 묶은 글(여행 편)은 가게마다 ② 인용구(이름) → ③ 지도 → ⑥ 반복을 되풀이하고, ④ 정보 인용구는 생략한다.

### ⑥ 반복 부분의 순서

사진 분류(`category`)와 실제 글의 흐름은 이렇게 맞춘다. 이 순서가 대부분의 글에서 지켜진다.

| 순서 | 내용 | 앱의 사진 분류 |
|---|---|---|
| 1 | 가게 찾아가기, 외관, 간판, 웨이팅 줄 | `EXTERIOR` |
| 2 | 메뉴판, 메뉴 구성 | `MENU` |
| 3 | 내부, 좌석, 분위기, 셀프바, 화장실, 기본찬 | `INTERIOR` |
| 4 | "저는 ○○ 주문했습니다" | (메뉴 사진 또는 전체 상차림) |
| 5 | 음식별 맛 묘사 (음식 하나에 사진 1~2묶음) | `FOOD_ITEM:메뉴명` |
| 6 | 총평과 맺음말 (마지막 음식 글에 이어서 씀) | `RECEIPT` → 5절 참고 |

## 2. 사진 블록

- **2장 묶음이 기본이다.** 1장, 3장은 가끔 쓴다. (5편 사진 블록 60개: 2장 62%, 1장 22%, 3장 17%)
- 한 묶음은 같은 장면이다. (외관 2장, 같은 음식 2장 등)
- 캡션은 거의 쓰지 않는다. 쓸 때는 `[메뉴A, 메뉴B]`처럼 대괄호 안에 메뉴 이름만 쓴다.
- 글 하나 앞에 사진 하나가 오는 것이 기본이다. 사진 두 묶음이 연달아 오는 경우는 드물다.

## 3. 가게 정보 인용구 (④)

항목마다 한 줄씩, 아는 항목만 쓴다.

```
🚩위치 : 서울 ○○구 ○○로 00 1층
⏳영업시간 : 매일 00:00 - 00:00 / 라스트오더 00:00
📞전화번호 : 000-0000-0000
📰가게정보 : (네이버 플레이스 편의시설 항목을 쉼표로)
🚗주차 : ○○ 공영주차장 (도보 0분)
```

- `📰가게정보`는 네이버 플레이스의 편의시설 목록을 쉼표로 이어 쓴다.
- 브레이크타임은 영업시간 줄 끝에 `[브레이크타임 00:00~00:00]`처럼 붙인다.

## 4. 글 블록의 문체

### 모양
- **한 문장을 2~4줄로 짧게 끊어 쓴다.** 모바일에서 가운데 정렬로 읽기 좋은 길이로, 한 줄 길이는 중앙값 13자이고, 절반이 10~16자다. 가장 눈에 띄는 특징이다.
- 글 블록 하나는 2~10줄이다.
- 블록 안에서 화제가 바뀌면 `.` 한 글자만 있는 줄로 띄운다.
- 맺음말 앞에는 `.` 줄을 두 번 쓴다.

### 말투
- 기본은 `~요`체이고 `~습니다`가 섞인다. (`방문했습니다!`, `주문했습니다`)
- 자주 쓰는 어미: `~더라구요`, `~구요`, `~거 같아요`, `~있어요!`, `~습니당`/`~주십니당` (가끔, 귀엽게)
- 감탄과 강조: `정말`, `정말정말`, `너무`, `쫙~`, `정말~~`
- 이모지는 **문장 끝에 1개**가 기본이다: 😊 😋 🤩 💕 👍 😥 🙁 😓 🤣 🍗 🌟
- 1인칭은 `저는`이다.

### 내용 습관
- 구체적인 사실을 쓴다: 방문 요일과 시간, 웨이팅 시간, 몇 인분, 가격, 예약 앱
- **단점도 솔직하게 쓴다.** 불편했던 점이나 아쉬웠던 맛을 가볍게 한두 줄 쓴다. 칭찬만 있으면 다른 사람 글처럼 보인다.
- 다른 리뷰에서 본 평가와 직접 먹어 본 느낌을 비교한다.
- 메뉴 조합이나 방문 시간 같은 작은 팁을 준다.

### 쓰지 않는 표현
- 과장된 광고 말투: `인생 맛집`, `미쳤다`, `역대급`, `강력 추천드립니다`
- AI 같은 설명 말투: `다양한 메뉴를 제공합니다`, `~를 경험할 수 있습니다`, `특히`, `또한`
- 섹션 제목, 해시태그 나열, 별점 기호(⭐⭐⭐⭐)

## 5. 인사와 맺음말

### 인사 (①)
- `안녕하세요 😊` / `안녕하세요~` / `안녕하세요~!`로 시작한다.
- 날씨나 계절, 상황 한마디를 한다.
- "오늘은 ○○에 다녀왔다"는 방문 소개 한 줄로 이어진다. (솔직 후기라는 점을 밝히기도 한다)
- **매번 다르게** 쓴다. 고정 문구를 쓰지 않는다.

### 맺음말 (⑦, 마지막 글 블록의 끝)
```
.
.
(한두 문장 총평)
(재방문 의사 한 줄: 다음에 먹어 보고 싶은 메뉴와 함께)
👍○○ 추천합니다👍          ← 앞뒤를 같은 이모지로 감싼다
(빈 줄)
💕(감사 인사 고정 문구)💕
```

- 감사 인사는 매 글 같은 문구다. 정확한 문구는 크롤링한 글의 마지막 줄에서 가져온다 (저장소에는 적지 않는다).

## 6. 제목

기존 제목 패턴은 두 가지다.

```
[가게명] 지역 특징 메뉴 맛집/카페 내돈내산 추천
가게명 지역 메뉴맛집 솔직리뷰 (메뉴, 메뉴, 키워드)
```

- 지역은 **동/역 이름이나 쇼핑몰 같은 랜드마크**다 (예: ○○동, ○○역).
- `내돈내산`, `솔직리뷰`, `추천`, `맛집추천` 중 1~2개를 넣는다.
- 괄호 안에는 대표 메뉴나 검색 키워드(웨이팅, 예약 앱 이름 등)를 쓴다.

## 7. "조금 더 이쁘게" (2026-11-12 사용자와 정한 개선 범위)

기존 글보다 **아래 4가지만** 낫게 한다. 그 밖의 문체는 바꾸지 않는다.

| 개선 | 기준 | 지켜야 할 선 |
|---|---|---|
| **사진 설명을 조금 더 풍부하게** | 사진 뒤 글을 3~6줄로. 맛, 식감, 양, 온도, 같이 먹으면 좋은 조합 같은 구체적인 정보를 더한다 | 줄 길이와 말투는 그대로. 사진에 보이지 않거나 사용자가 알려주지 않은 사실은 지어내지 않는다 |
| **재방문 의사를 항상 넣기** | 맺음말에 재방문 의사 한 줄 | 사용자가 입력한 만족도(별점, 메모)와 맞아야 한다 |
| **내돈내산 밝히기** | 인사나 맺음말에 `내돈내산` 한 번. 영수증 사진(`RECEIPT`)이 있으면 맺음말 바로 앞에 1장으로 배치한다 | 실제로 직접 결제했을 때만 쓴다 (사용자 확인 항목으로 둔다) |
| **검색 노출용 제목** | 6절 패턴 안에서 지역(동/역) + 대표 메뉴 + 가게명 + `내돈내산`/`솔직리뷰` + 괄호 키워드를 고른다 | 제목 패턴을 벗어나지 않는다 |

### 아직 정하지 않은 것
- **내돈내산 이미지:** 맺음말에 넣을 "내돈내산" 배지 이미지가 있는지 여자친구에게 확인한다. 있으면 그 이미지를 쓰고, 없으면 영수증 사진으로 대신한다.
- 원본 글의 오타는 따라 하지 않는다. 일부러 오타를 내는 것은 하지 않는다.

## 8. 앱 구현에 필요한 변경 (3~5단계 할 일)

| 위치 | 필요한 변경 |
|---|---|
| `gemini_service.py` 글쓰기 프롬프트 | 7개 고정 섹션, `[섹션명]` 태그, `'욱스'` 인사말을 이 명세로 교체. 실제 글 1~2편을 블록 형태 그대로 예시로 넣는다 |
| `BlogPostBlock` 스키마 | `map` 블록 사용, `quote`의 `style`(`default`/`quotation_line`)을 반드시 채우게 한다 |
| 편집 화면 `post_editor_screen.dart` | 지금은 글 맨 앞의 `[섹션명]`으로 섹션을 나눈다. 태그가 없어지므로 다른 기준이 필요하다 (예: 사진 블록마다 섹션 하나) |
| 발행 봇 `naver_v2.py` | 지도(장소) 블록 삽입, 인용구 스타일 선택, `.` 줄과 짧은 줄바꿈 유지 |
